# Agent instructions

A one-hunk patch that makes squeekboard use the Wayland OVERLAY layer instead of TOP, plus `build.sh`, which fetches the Raspberry Pi OS source package, applies the patch and builds a `.deb`. This file is the single index for anyone, human or tool, changing the repo.

## Check

`make check` runs the offline gate: `shellcheck build.sh`, `python3 tools/gen_diagram.py --check` (generated SVGs are current) and `python3 tools/check_docs.py` (no em or en dashes, every `docs/*.md` indexed). `make patch-check` also downloads upstream `src/panel.c` and dry-runs the patch against it. CI runs the same checks, and also dry-runs the patch against the Raspberry Pi fork and asserts the result selects `OVERLAY` and no longer references `TOP`. A weekly CI run catches upstream drift. There is no unit-test suite.

`make diagram` redraws the SVGs in `docs/assets/`. `make social-preview` needs Google Chrome and is not part of the gate.

## Layout

| Path | What lives there |
|---|---|
| `overlay-layer.patch` | the patch, one hunk in `src/panel.c` |
| `build.sh` | fetch source, apply the patch, build the package; runs on a Raspberry Pi |
| `tools/` | diagram generator, docs checker, vendored brand kit |
| `docs/` | setup, how it works, FAQ, troubleshooting; index in `docs/README.md` |
| `llms.txt` | one-page summary for search engines; keep it true |

Root holds only README, LICENSE, SECURITY, CONTRIBUTING, AGENTS (`.md`), `llms.txt` and config files.

## Do not change

- The patch file name and the arguments of `build.sh` (squeekboard version, work directory): the docs and users' scripts call them.
- The package name `squeekboard` and the default version in `build.sh`: they must match what apt offers on Raspberry Pi OS, and the docs tell users to hold the package.
- Keep the patch minimal. A change that is not needed to select the OVERLAY layer belongs upstream.

A change reaches a Pi only when its owner rebuilds and installs the package.

## Rules

- Documentation must be true of the code: every command, flag and version. Run a command before documenting it. No hand-typed counts that can drift.
- Commits are conventional (`fix:`, `feat:`, `docs:`, `refactor:`, `ci:`, `chore:`) and authored by the repo owner. No co-author trailers, session ids or "generated by" lines in commits, PRs, issues or comments.
- Never force-push `main` and never commit secrets, keys, tokens, IP addresses, private hostnames or personal e-mail. The one public contact address is caputodav@gmail.com.
- Style: directories `lowercase-kebab`, shell scripts `kebab-case.sh`, Python `snake_case`, docs `docs/lowercase-kebab.md`. No em dashes in new copy.
- README keeps its shape: centered header, emoji `##` headings separated by `---`, the architecture diagram drawn by `tools/gen_diagram.py`, a repo tree that matches `git ls-files`, and the credit footer as the last line.
